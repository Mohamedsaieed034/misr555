# نظام صيدلية مصر الذكية

نظام تدريب وإدارة داخلي للصيادلة (دليل أدوية، اختبارات، دليل تأمين، تطوير دوائي)، مبني على Cloudflare Pages + Cloudflare Functions + قاعدة بيانات D1 مشتركة. **كل البيانات مشتركة الآن بين كل الأجهزة** — أي تعديل من أي جهاز يظهر لكل المستخدمين الآخرين.

## الملفات

```
pharmacy-app/
├── index.html          ← هيكل الصفحة
├── style.css            ← التنسيق والتصميم
├── script.js            ← منطق التطبيق (يتصل بواجهة /api لكل البيانات)
├── schema.sql            ← بنية قاعدة بيانات D1 (تُشغَّل مرة واحدة فقط)
├── functions/
│   ├── _lib/auth.js      ← تشفير كلمات المرور وإدارة رموز الجلسات
│   └── api/
│       ├── login.js       ← تسجيل الدخول + التحقق من IP على مستوى الخادم
│       ├── bootstrap.js   ← إنشاء أول حساب مدير بأمان
│       ├── quiz-logs.js   ← سجل نتائج الاختبارات (مشترك)
│       ├── history.js     ← سجل نشاط النظام (مشترك)
│       ├── state/
│       │   └── [key].js         ← بيانات الأدوية وبيانات التأمين (مشتركة)
│       └── users/
│           ├── index.js         ← قائمة المستخدمين + إنشاء حساب
│           └── [username].js    ← تعديل/حذف حساب محدد
└── README.md
```

## ما الذي أصبح مشتركاً بين كل الأجهزة الآن

| البيانات | أين كانت | أين أصبحت |
|---|---|---|
| حسابات المستخدمين وصلاحياتهم | محلي (متصفح كل جهاز) | ✅ قاعدة بيانات مشتركة |
| بيانات الأدوية (المراحل الثمانية) | محلي | ✅ قاعدة بيانات مشتركة |
| بيانات التأمين (الشركات، الشروط، الأماكن، التشخيصات) | محلي | ✅ قاعدة بيانات مشتركة |
| سجل نتائج الاختبارات | محلي | ✅ قاعدة بيانات مشتركة |
| سجل نشاط النظام | محلي | ✅ قاعدة بيانات مشتركة |
| إعدادات الدخول المباشر (Auto-Login) | محلي | يبقى محلياً عمداً — هذا إعداد خاص بكل جهاز على حدة، وليس بيانات تطبيق |

**نتيجة مهمة:** التطبيق الآن **لا يعمل إلا على الموقع المنشور فعلياً على Cloudflare Pages** (مع ربط قاعدة بيانات D1 والـ Functions كما بالخطوات أدناه). فتح الملف المدمج (`gemini-code-....html`) محلياً بالدبل كليك **لن يستطيع تسجيل الدخول أو عرض أي بيانات** بعد الآن، لأنه لا يوجد خادم يستجيب لطلبات `/api/...`. الملف المدمج مفيد فقط لمعاينة التصميم البصري.

## خطوات النشر والإعداد لأول مرة

### 1. رفع الملفات
ارفع محتويات هذا المجلد (بما فيها مجلد `functions/`) إلى مستودع GitHub (يُفضّل خاص).

### 2. ربط Cloudflare Pages
Workers & Pages → Create → Pages → Connect to Git → اختر المستودع. لا حاجة لأمر بناء (Build command فارغ)، ومخرجات البناء هي المجلد الجذر.

### 3. إنشاء قاعدة بيانات D1
في Cloudflare Dashboard:
1. Workers & Pages → D1 → Create database → اختر اسماً مثل `pharmacy-db`.
2. افتح تبويب **Console** في قاعدة البيانات، الصق محتوى ملف `schema.sql` بالكامل، ونفّذه (مرة واحدة فقط).

### 4. ربط القاعدة بمشروع Pages
مشروع Pages → Settings → Functions → **D1 database bindings** → Add binding:
- **Variable name:** `DB` (بالضبط كما هو، لأن الكود يستخدم `env.DB`)
- **D1 database:** اختر `pharmacy-db`

### 5. إضافة السر الخاص بتوقيع الجلسات
مشروع Pages → Settings → Environment variables → أضف متغيراً سرياً (Secret، وليس Variable عادي):
- **الاسم:** `APP_JWT_SECRET`
- **القيمة:** أي نص عشوائي طويل وقوي (32 حرفاً أو أكثر) — لا تشاركه مع أحد.

بعد إضافة الـ binding والسر، أعد نشر المشروع (Retry deployment) حتى تُطبَّق التغييرات.

### 6. إنشاء أول حساب مدير
افتح رابط الموقع المنشور — بما أن قاعدة البيانات فارغة، ستظهر شاشة "إنشاء أول حساب مدير" تلقائياً بدل شاشة الدخول العادية. أنشئ حسابك بها، ثم سجّل الدخول.

### 7. (اختياري) ترحيل بياناتك القديمة
إذا كان عندك بيانات أدوية أو تأمين محفوظة من قبل على جهاز معين (بالنسخة القديمة من التطبيق)، افتح تلك النسخة القديمة على نفس الجهاز، اضغط "تصدير وحفظ ملف البيانات الحالي (.json)" من قسم إعدادات التعاقدات، ثم في التطبيق الجديد المنشور، سجّل دخول كمدير واستخدم "استيراد ملف الداتا" لرفع نفس الملف — سيُحفَظ تلقائياً في قاعدة البيانات المشتركة الجديدة.

## ملاحظات أمان

- كلمات المرور تُخزَّن مشفّرة (PBKDF2 + ملح عشوائي لكل مستخدم) — لا يمكن لأحد، ولا حتى المدير، رؤيتها كنص صريح بعد الإنشاء.
- تقييد IP لكل حساب يُتحقق منه على الخادم باستخدام العنوان الحقيقي الذي يرسله Cloudflare (`CF-Connecting-IP`)، وليس عنواناً يبلّغ عنه المتصفح.
- استخدم أيضاً قاعدة WAF على مستوى Cloudflare (Security → WAF → Custom rules) لتقييد الوصول لعناوين IP مكاتبك الثابتة كطبقة حماية إضافية على مستوى الشبكة كلها.
- بيانات الأدوية وبيانات التأمين لا تُقيَّد بصلاحية "مدير" وحده في الخادم لتحديث الأدوية تحديداً (لأن شاشة "التطوير الدوائي" متاحة افتراضياً لكل الأدوار)، بينما تعديل بيانات التأمين (قسم "إعدادات التعاقدات") مقصور على "مدير" فقط، مطابقةً لقفل الشاشة بالواجهة.

## التشغيل محلياً (للمعاينة فقط)

افتح `index.html` مباشرة لمعاينة الشكل والتصميم فقط. لا شيء تفاعلي سيعمل (لا تسجيل دخول، لا بيانات) لأن كل شيء الآن يعتمد على Functions وD1، وهما يحتاجان بيئة Cloudflare الفعلية. للتطوير المحلي الكامل يمكن استخدام أداة Wrangler (`wrangler pages dev`) — إن احتجت ذلك أخبرني وسأجهزه.
